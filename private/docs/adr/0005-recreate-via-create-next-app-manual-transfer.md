# Пересоздание проекта через create-next-app + ручной постраничный перенос вместо копирования

Исходно (см. ADR 0001) план был: скопировать рабочий v0.7.0-код в новую папку, почистить, запушить. По ходу выяснилось: весь этот код целиком написан Claude Code в предыдущих сессиях, а владелец проекта не имеет опыта в JS/TypeScript/React и не понимает, что в нём происходит — просто скопировав код, он получил бы второй раз рабочий сайт, которым не может ни управлять, ни объяснить, ни отладить сам.

Решено: не копировать. Вместо этого — запустить официальный `npx create-next-app@latest` заново, с владельцем, отвечающим на каждый вопрос мастера осознанно (TypeScript/ESLint/Tailwind/src-директория/App Router — каждый выбор объяснён простыми словами). Дальше старый рабочий код (сохранён нетронутым отдельно) переносится обратно вручную, файл за файлом, в порядке от фундамента к видимому (`lib`/`db` → `components` → страницы, начиная с лендинга → тесты в самом конце) — с объяснением каждого шага. Автоматизировать/делегировать агенту этот перенос нельзя: цель не «получить работающий код быстро», а «чтобы владелец сам понимал свой продукт».

**Considered options**: перенести код как есть и объяснять постфактум по вопросам — отклонено, пассивное чтение чужого кода не даёт того же понимания, что активное пересоздание; нанять/дождаться университетскую команду и переложить понимание на них — отклонено, команда не гарантирована (зависит от одобрения курса), а владелец как единственный текущий разработчик должен быть независим от кода уже сейчас.
