# Бэкенд-стек — PostgreSQL + Prisma + Auth.js + MinIO в Docker Compose

Проект задуман как коммерческий, в перспективе — хостинг на собственном VDS через Docker. Для будущих data-driven фич (профиль, вес, обхваты — на нескольких устройствах и, позже, у нескольких пользователей) зафиксирован бэкенд-стек:

- **PostgreSQL** — база данных.
- **Prisma** — ORM. Выбран вместо Drizzle из-за более низкого порога входа и лучшей документации — в команде будут студенты из универа с разным уровнем backend-опыта.
- **Auth.js (NextAuth v5)** — аутентификация, self-hosted, без вендор-лока.
- **MinIO** — S3-совместимое хранилище файлов (пригодится для фотофиксации результата — идея из заметок 16.09).
- Всё поднимается через `docker-compose` рядом с контейнером самого Next.js-приложения на VDS.

Реализация откладывается: в v1.0.0 бэкенда нет вообще (см. [0002](./0002-v1-scope-landing-only.md)), код пишется, когда реально строятся страницы `/profile`, `/weight`, `/measurements` в их серверной версии.

**Considered options**: Drizzle ORM (легче, ближе к SQL, но выше порог входа для новичков в команде) — отклонён; Supabase self-hosted (бандл БД+auth+storage) — отклонён как более тяжёлый в операционном плане для команды из 2–3 человек.
